# UltraPDF (PDF Читалка)

Простой просмотрщик PDF для Android: WebView-интерфейс + системный PdfRenderer.
Пакет `com.dd.pdfviewer`, minSdk 21, targetSdk 34.

Возможности: ленивая отрисовка страниц (страницы отдаёт приложение напрямую в WebView, без передачи через JS), щипок и двойной тап для масштаба,
переход на страницу, ночной режим (инверсия страниц на стороне приложения), запоминание позиции, открытие последнего файла, открытие PDF из других приложений,
меню: открыть, история (10 последних документов), день/ночь, поиск по тексту (Android 15+, встроенный PdfRenderer), поделиться, сохранить как, о приложении (проверка обновлений, поделиться приложением, GitHub).
Тап по странице плавно прячет обе панели.

**Режимы.** В меню есть переключатель Pro. Обычный режим: открыть, история, день/ночь, поиск, поделиться, сохранить как, о приложении (как в 1.4). Режим Pro добавляет: закладки, оглавление, ссылки внутри документа, текст страницы (выделить и скопировать), печать, поворот документа по 90° (запоминается), пароль на PDF, внешний вид (день/сепия/ночь, светлая или тёмная тема приложения, яркость экрана), полный экран (выход всегда виден крестиком в правом верхнем углу).

Для оглавления, ссылок и текста страницы внутри лежит pdf.js 3.11.174 (Apache-2.0, `assets/pdfjs/`), грузится только когда нужен.

Готовый APK: `UltraPDF.apk` (подпись ключом dbg.jks, тем же, что у TITAN RAID).
Автообновление: при запуске приложение читает `version.json` из этого репозитория (ветка main) и, если `code` больше установленного, предлагает скачать и установить `UltraPDF.apk`. Для новой версии увеличить `code`/`name` в `version.json` и заменить APK.

Сборка: `SDK=/path/to/sdkmin KS=/path/to/dbg.jks ./build.sh <versionCode> <versionName> out.apk`
(aapt2 → javac → d8 → zipalign → apksigner). Внутренние нестатические классы в Java не использовать: d8 8.2 на них падает.

Тесты (без телефона): `node tests/ui_test.js assets/index.html` (интерфейс на заглушке DOM), `node tests/pdfjs_helpers_test.js` (оглавление, ссылки, текст на настоящем pdf.js и `tests/fixture.pdf`), `python3 tests/e2e_browser.py /tmp/e2e` (настоящий Chromium через Playwright, приложение имитируется).

## Windows (`windows/`)

Нативный просмотрщик под Windows 10/11 x64: один портативный файл `UltraPDF.exe` (C++17, Win32 + GDI+, рендер PDFium, всё внутри exe; при первом запуске `pdfium.dll` распаковывается в `%LOCALAPPDATA%\UltraPDF`).
Вкладки, миниатюры/оглавление/закладки в боковой панели, плавная прокрутка, масштаб (колесо с Ctrl, по ширине/странице), поиск (в том числе по кириллице без учёта регистра), выделение и копирование текста, ссылки и возврат (Alt+←), поворот, печать, пароль, день/сепия/ночь, полный экран и презентация (F5), перетаскивание файлов, история, сессия вкладок, ассоциация с .pdf.
Режим Pro (как на телефоне) по умолчанию включён.
При запуске показывается заставка (логотип и название): не меньше 1 с, закрывается, когда открыты вкладки и первая страница отрисована (не дольше 8 с).
Страницы до ~12 Мпикс рендерятся целиком (порог `IsSingle` в `view.cpp`, `ULTRAPDF_SINGLE_MP` для опытов), большие — плитками 1024x768.
Кэш плиток вытесняет в первую очередь страницы, самые далёкие от экрана, превью соседних страниц ограничены по числу и размеру (иначе они вытесняли видимые плитки и вызывали бесконечную дорисовку).
Автообновление: читает `version-win.json` из этого репозитория, скачивает `UltraPDF.exe`, проверяет SHA-256 и подменяет себя. Для новой версии: собрать, положить `UltraPDF.exe` в корень, обновить `code`/`name`/`sha256` в `version-win.json`.
Подписи кода нет, поэтому SmartScreen при первом запуске предупреждает («Подробнее» → «Выполнить в любом случае»).

### UltraPDF Editor (`UltraPDF-Editor.exe`)

Отдельное приложение на базе вьювера (сборка: `cd windows && EDITOR=1 ./build.sh`, исходники `editor*.cpp`, `export.cpp`). Тройной переключатель в строке вкладок: **Просмотр** / **Pro** / **Редактор** (Ctrl+1/2/3).
Редактор: маркер, подчёркивание, зачёркивание, волнистая линия, текст (кириллица), рисование, прямоугольник, эллипс; вставка картинки (подпись, печать с прозрачным фоном из PNG) с перемещением, изменением размера и слоями (на передний/задний план, вперёд/назад); цвет, толщина, размер шрифта; отмена/повтор; операции со страницами (поворот, удаление, перестановка, пустая страница, вставка из файла, извлечение, разделение).
Подписи и печати хранятся в `%APPDATA%\UltraPDF Editor\stamps`.
«Сохранить как…» с параметрами: как есть; для суда («Мой Арбитр»: документ без интерактива / скан серый / скан ч/б / скан цветной, 200 dpi, лимит 30 МБ с автоподбором); для почты; свои (dpi, цветность, качество JPEG, лимит МБ). Электронная подпись (отсоединённая .sig) делается отдельно.
Автообновление: `version-editor.json` + `UltraPDF-Editor.exe` в корне.

Сборка (Linux, кросс-компиляция): `cd windows && TC=/path/llvm-mingw PDFIUM_INC=/path/pdfium/include ./build.sh` (нужны llvm-mingw и pdfium-win-x64 от bblanchon; `res/pdfium.dll` кладётся в ресурсы).
Тесты: `windows/tests/run.sh tN.txt <сек>` запускает exe под Wine с переменной `ULTRAPDF_TEST=<скрипт>` (команды open, cmd, click, shot, info и т.д.), примеры в `windows/tests/`. Замер прокрутки: `ULTRAPDF_TRACE=<файл>` пишет строку на каждую отрисовку, `python3 windows/tests/scrolltrace.py <файл>` считает кадры с недорисованными плитками (сценарий `t25.txt`). Заставку в тестах включает `ULTRAPDF_SPLASH=1`. Масштабирование щипком / Ctrl+колесо: растягивается снимок экрана (`ViewPinch` в view.cpp), настоящая раскладка и плитки следуют за щипком каждый кадр, резкий снимок растягивается при увеличении, окончательная картинка рисуется, когда ввод затих; сценарий `t26.txt`. Касание: два пальца масштабируют по сырым позициям пальцев (WM_POINTER), без ожидания распознавателя жестов Windows. Кадр выводится целиком через DXGI flip-цепочку (`windows/src/present.cpp`, без неё и без GPU работает прежний BitBlt; `ULTRAPDF_NOFLIP=1` отключает), чтобы DWM не забирал полуотрисованное окно (разрывы кадра). Двойной клик и перетаскивание с зажатой кнопкой по вертикали = масштаб (вверх — увеличить, вниз — уменьшить; сценарий `t29.txt`). Меню «Настройки → Рендеринг» (вывод кадра в DirectX идёт из отдельного потока, чтобы Present не блокировал UI; при смене режима окно документа пересоздаётся): авто (AMD → загрузка кадра через кольцо staging-текстур + CopyResource, остальные → UpdateSubresource; на AMD Ryzen Z2 Extreme UpdateSubresource в буфер цепочки давал цветной мусор), классический BitBlt, плавный для NVIDIA/Intel, плавный для AMD. Переменная ULTRAPDF_FLIPMODE=0..3 переопределяет режим для тестов.
